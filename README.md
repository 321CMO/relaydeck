# RelayDeck

面向个人和朋友使用的多服务器节点管理面板。目标是从空白 VPS 安装开始，在一个面板中创建节点、配置内网落地与分流，并用一个订阅地址交付每位用户的全部授权节点。

项目仓库：[321CMO/relaydeck](https://github.com/321CMO/relaydeck)。

**当前处于设计阶段，没有可安装的正式版本。** 开源许可证待确定；已有功能规格和离线流程模型，尚未实现面板、Agent、代理配置编译器和安装器。

## 第一版范围

- 一个中心面板管理多台 VPS，每台可以创建多个节点。
- VLESS Reality、Hysteria 2（连续端口跳跃）、SS2022。
- 每位用户独立认证，一个订阅地址聚合跨服务器的授权节点。
- 适配 Clash Verge 与 Shadowrocket；客户端分流、DNS、策略组和服务端出口规则。
- “选择入口节点 → 选择落地机 → 检查并启用”的 A→B 线路，优先使用云厂商原生内网。
- 官方脚本与中文管理菜单，涵盖中心/节点安装、升级、回退、诊断、备份恢复和卸载。
- 配置任务与生效版本、跨服务器用量、可选额度/到期、日志及失败恢复。
- Telegram 故障/恢复告警、每日摘要、到期/额度提醒、只读查询与可选朋友绑定。
- 六个主页面、四步交付引导、统一检查应用、计划备份与管理员找回。

## 开发与 GitHub 交付

使用 `codex/` 开发分支提交改动，以 PR 提供完整功能、变更说明和验证结果。发布使用版本标签与 GitHub Releases，提供固定版本的预编译包、安装入口、校验清单、兼容矩阵和更新说明。

建议开发顺序：

1. 锁定核心与客户端验证版本，验证三种协议、用户统计、HY2 跳跃和内部 SS2022 连接。
2. 实现中心、Agent、服务器身份、任务回执、配置编译与失败恢复。
3. 实现节点、用户授权、聚合订阅、分流与可视化操作。
4. 实现安装器、升级回退、备份恢复、卸载与发布流水线。
5. 在真实 VPS 和客户端中完成验收，再发布可安装版本。

当前优先验证 sing-box 统一核心；Go 后端/Agent、React/TypeScript 前端、SQLite、systemd、Caddy 为计划实现方向。

## 真实 VPS 验收

| 环境 | 可以验证的内容 |
| --- | --- |
| 一台空白 VPS | 中心与节点共存、端口隔离、安装中断重试、三个协议、证书、订阅、升级/迁移失败回退、备份恢复、卸载 |
| 两台原生内网互通 VPS | 多服务器管理、A→B 真实 TCP/UDP/DNS 与出口、落地断线阻断、两端部分应用恢复、内网规则、用量去重 |
| 实际 Clash Verge / Shadowrocket | 导入、刷新、认证隔离、分流与 DNS、策略组、HY2 持续跳跃和 SS2022 兼容性 |

一台 VPS 内的模拟可用于预检查，但不能作为两台云服务器原生内网互通的验收证据。

## 离线设计检查

需要 Node.js 18 或更新版本；这些检查不安装服务、不访问网络、不证明实际协议连接可用。

```sh
node simulation/verify-relay-lifecycle.cjs
node simulation/verify-notification.cjs
```

结果文件分别标记离线设计模型、`realDeploymentTested: false` 或 `realTelegramTested: false`。正式安装命令待安装器和 Release 通过验收后补充。
