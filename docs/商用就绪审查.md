## 结论与适用范围

**当前不具备面向客户长期运营的生产就绪证据。定位仍是开发预览，可继续在明确知晓限制的自用、朋友试用环境中验证。** 单台 VPS 的主要功能链路已通过，不代表多机可用性、故障恢复、持续运行、容量和完整安全审查已通过。

这里的商用基线是：一个运营者管理多台 VPS，为订阅使用者稳定提供服务；不引入支付、订单、拼车规则或多商户系统。安全检查参考 [OWASP ASVS](https://owasp.org/projects/asvs)，服务指标参考 [Google SRE 的 SLO 方法](https://sre.google/sre-book/service-level-objectives/)。本报告是项目审查，不是 ASVS 认证，也没有完成全部标准条目的验证。

本轮只读检查源码、GitHub 发布状态与真实 VPS 服务状态；新增本地隔离复现和依赖扫描。未更改线上配置、密码、订阅、端口或服务，也没有在线触发错误登录锁定、断网或压力测试。

## 上线前必须关闭的项目

以下“门槛”表示不应在未处理或未完成验证时宣布生产稳定，不等于每项都是已被利用的安全漏洞。

### COM-001：反向代理后的登录限流误伤全部管理员（P1，已隔离复现）

- 位置：`internal/panel/app.go:219`、`internal/panel/auth.go:98`、`internal/panel/config.go:366`。
- 根因：以 `r.RemoteAddr` 的 IP 作为登录失败桶。正式部署经 Caddy 转发到 `127.0.0.1:8787`，后端看到的是反向代理的地址；没有可信代理客户端地址提取逻辑。
- 结果：能访问管理入口的人连续输错 5 次，其他来源即使输入正确密码也会收到 429，最长影响当前 15 分钟窗口。安全路径降低入口暴露概率，不能修复此隔离问题。
- 本次本机临时数据库 + HTTP 反向代理复现：首次设置 200；来源 A 的 5 次错误登录均 401；另一个转发来源 B 使用正确密码得到 429。未对线上执行错误登录测试。
- 验收：只有已配置可信代理能提供客户端地址；忽略/清洗外部伪造转发头；两个真实独立来源互不误伤，同时保留账号级防爆破与总体资源保护；覆盖 IPv4、IPv6、多层代理和重启行为。
- 不应简单改成无条件信任任意 `X-Forwarded-For`。

### COM-002：依赖扫描命中已知漏洞，尚未修复与回归（P1，扫描确认，利用条件需分开评估）

- 本次使用 Go 官方 `govulncheck` v1.9.0，扫描当前源码 `./...`。工具执行完成并返回发现漏洞状态，项目 `go.mod/go.sum` 未修改。
- 命中 `google.golang.org/grpc v1.79.1` 的两个可达符号报告：[GO-2026-6348](https://pkg.go.dev/vuln/GO-2026-6348)（HTTP/2 分片导致内存耗尽，公告修复版本 v1.83.1）、[GO-2026-6061](https://pkg.go.dev/vuln/GO-2026-6061)（xDS/RBAC 和 HTTP/2 transport，公告修复版本 v1.82.1）。不能仅按包名推断本项目使用了 xDS 或存在公网授权绕过。
- 调用链入口为 `internal/agent/traffic.go:98` 的本机统计 gRPC 客户端；连接目标固定 `127.0.0.1:10085`，配置也只监听回环，代理规则拒绝访问此端口。**目前没有证明公网可直接利用这些问题。** 静态可达报告与实际攻击前提应分别记录。
- 扫描另外报告了未见项目调用的包/模块级条目，不将它们合并宣称为可利用漏洞。
- 本次 `npm audit --omit=dev --json` 的生产依赖已知漏洞数量为 0；这不覆盖 Go、独立 sing-box/Caddy 二进制、开发工具或操作系统。
- 验收：选择包含所需修复且兼容的版本、重新构建，回归统计、三协议、重启恢复和发布包；把 Go/npm 与打包核心的漏洞检查加入发布门槛，逐项记录实际适用性和处置。官方工具的能力范围见 [Go Vulnerability Management](https://go.dev/doc/security/vuln/)。

### COM-003：中心失联会扩大为全部数据节点停服（P1，源码确认，灾难演练待做）

- 位置：`internal/panel/app.go:782` 发出 20 分钟租期；`internal/agent/agent.go:451` 租期过后停止核心。
- 这是当前防止离线授权无限有效的明确设计；不能直接删除或无限延长租期来宣称修好了可用性。
- 风险：中心主机、DNS、证书或同步链路故障，持续到各 Agent 租期届满后，即使节点数据链路正常，也会被停服。当前没有高可用中心和完整恢复时限证据。
- 验收：定义授权撤销和可用性的取舍、失联时显示与通知、可接受最长停服时间；演练中心长时间不可达、重启、证书失效、恢复后重新同步，检查授权到期、禁用和流量统计。可采用经验证的恢复方案或冗余设计，不强制为小规模部署引入集群。

### COM-004：全损恢复与离机备份证据不足（P1，能力缺口）

- 已有人工加密可移机中心备份、升级前同机快照和恢复处理；不应描述为“没有备份”。
- 仓库未提供计划离机备份与自动恢复验证，本次主机 timer 未发现 RelayDeck 定时备份；云厂商是否另有快照未验证。
- 数据库需独立 `master.key`；同机快照无法覆盖整台 VPS 丢失。独立口令备份能改善可移机性，但仍需验证全部相关资产。
- 验收：定义 RPO（最多丢失多久的数据）与 RTO（多久恢复），落实保留周期和访问权限；在全新主机恢复中心、Agent 身份与必要状态、TLS/ACME 资产，核对订阅地址、节点认证、统计不重复和授权撤销。不备份的资产须明确重建步骤。

### COM-005：主要宣传场景与客户端适配尚未实机闭环（P1，验证缺口）

- A→B 原生内网已有配置和本机进程测试，尚缺两台云 VPS 的 TCP/UDP/DNS、源地址、防火墙、落地宕机不直出的验收。
- Shadowrocket 目前 URI 订阅，分流和 HY2 跳跃仍未实现/验收；不能承诺与 Clash Verge 对等。
- 面板公开 CA 初次签发已通过；临期自动续期、失败告警、加载新证书和 HY2 共机证书协同仍缺完整生命周期验证。
- arm64 仅编译不足以证明安装和运行支持；可先限定正式支持的系统/架构，再按实测扩展。
- 验收：按明确支持矩阵实机跑通；未支持功能在 UI、文档和发布说明中标明，或完成后再交付。

### COM-006：生产可观测性与容量上限不明确（P1，验证与运维缺口）

- `/healthz` 当前反映 HTTP 实例响应，不检测实际代理握手。Agent 心跳、核心存活和任务成功不能替代用户侧服务可用性。
- TG 有验证、测试发送、持久通知队列和重试代码；此前主要用模拟接口验证，尚未真实 Bot 联调。中心自己宕机时，也不能依赖中心自己发送告警。
- `internal/panel/store.go:65`、`:138`：全局互斥锁、完整状态复制/加密、单连接写数据库；心跳统计和配置修改共享此路径。不能直接断言性能不足，但目前也没有支持规模证据。
- 验收：先声明 VPS 数、订阅数、节点数、规则数、请求负载和机器规格；测量接口延迟、错误率、CPU/内存、数据库体积、同步和发布延迟。建议持续负载 72 小时起步，并注入短时突发、统计增长、磁盘满、进程终止和弱网；持续时间是项目建议，不是通用认证标准。
- 需要中心之外的可用性探测和真实告警演练，验证离线/恢复、证书临期、发布失败、备份失败、重试及重复抑制。明确采样间隔与告警时延。

### COM-007：对外安装与开源发布尚未完成（发布门槛）

- 审查时 [PR #2](https://github.com/321CMO/relaydeck/pull/2) 仍为 draft，仓库 Release 列表为空；当前 CI 是保留 14 天的 development artifact。
- 安装、升级、回退和卸载脚本已有代码及部分实测，但尚没有用户可按固定正式版本复现的完整发布链路。
- 项目根许可证尚未选定；打包的上游许可证已有保留。公开仓库不能代替明确的项目授权说明。
- 验收：固定版本 tag/Release、完整包与摘要、升级说明、受支持系统、全新机器“一键安装→登记→交付→升级→回退→卸载/保留数据”验收；确定项目许可证并核对第三方发布材料。签名、构建证明和 SBOM 可加强供应链验证，应结合发行方式落实，不将某个工具名称当作商用资格。

## 建议推进顺序与验收判定

1. 先处理 COM-001 登录限流、COM-002 依赖问题并加入持续检查；复查公开入口的资源限制、错误脱敏和凭据轮换。
2. 明确 COM-003 中心故障策略，完成 COM-004 全损恢复；建立可从外部发现和恢复故障的能力。
3. 完成 COM-005 两机内网、客户端与证书周期验收；按 COM-006 测出实际支持规模并完成连续运行和告警演练。
4. 完成 COM-007 正式安装发布；仅在相关条件项兑现、缺陷关闭且留下可重现证据后重新评估生产就绪。

所有关闭记录需写明版本、环境、步骤、实际结果和未覆盖边界。先前功能测试可复用；新增修复必须回归受影响链路，不通过重复跑无关测试来替代缺失的故障或实机验收。
