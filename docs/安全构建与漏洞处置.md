# alpha.7 安全构建与漏洞处置

2026-10-16。此文记录构建和扫描范围，不能代替完整安全审查或生产验收。

## 三个独立组件

安装包包含 RelayDeck、sing-box 和 Caddy。面板依赖扫描通过，不能推断另两个二进制也通过。本次发现原 sing-box 包的依赖版本、原 Caddy 包的 Go 工具链和依赖均需要进一步处理，因此重新构建两个核心，而非继续复用旧官方二进制。

- RelayDeck 的 gRPC 更新至 v1.83.2。
- sing-box 使用固定 v1.14.3 官方源码；`core-security-overrides.json` 明确覆写相关安全依赖。版本标为 `1.14.3-relaydeck.1`。
- Caddy 使用固定 v2.11.7 官方源码；使用 Go 1.27.2 和 `caddy-security-overrides.json`，版本标为 `v2.11.7-relaydeck.1`。

两份上游源码 ZIP 的模块摘要和 go.mod 摘要固定校验。构建在独立副本内进行，不修改模块缓存；业务源码保持原样，**依赖图已更改**，不能把产物称为未经修改的官方发行二进制。

与程序包一同提供来源 ZIP、构建脚本、安全覆写清单、解析后的 `.mod/.sum` 和构建记录。构建记录保存依赖文件 SHA256；分发文件由 SHA256SUMS 覆盖。重新构建仍会访问 Go 模块代理/校验服务，未宣称已实现完全离线或逐字节可复现构建。

## 扫描方式和边界

使用 Go 官方 `govulncheck v1.9.0`：面板扫描 `./cmd/... ./internal/...`；核心扫描实际入口，sing-box 使用与编译一致的 `with_quic,with_utls,with_acme,with_clash_api,with_v2ray_api` 标签，指定目标 GOOS/GOARCH。源码中存在调用链的已知漏洞会阻止 CI 继续打包。

本次 amd64 Linux 与本机 darwin arm64 的两个核心扫描均未发现可达漏洞；面板源码扫描亦为 0。扫描还报告依赖图内存在未发现调用的模块级问题；这不等于整个依赖图没有任何公告。

尤其 `golang.org/x/crypto/openpgp` 的 [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) 没有修复版本。带当前标签和入口的源码扫描未发现实际导入或调用该包的链路，按“模块存在、当前构建调用不可达”记录，未通过关闭扫描或编造修复版本忽略它。新增 OpenPGP 功能、构建标签、入口或依赖后必须重新评估。

旧发行二进制的扫描会报告更多符号与模块级条目；二进制扫描可见的符号不自动代表公网可利用。项目源码的 gRPC 客户端只连接回环统计端口；统计服务端的修复版本仍需覆盖，因此两个组件均升级至 v1.83.2。面板和核心的安全结论分别记录。

CI 另执行 `npm audit --omit=dev`。它只覆盖生产 npm 依赖的公开公告。未覆盖操作系统补丁、开发工具的完整漏洞审查、未知漏洞和渗透测试。

## 登录限流与升级

Caddy 以真实 socket 对端覆盖 `X-RelayDeck-Client-IP`，Go 后端只接受本机反向代理提供的单个有效 IP，忽略任意 `X-Forwarded-For`。生产入口来自回环但缺少合法专用头时返回 503，不落到共享 loopback 失败桶。IPv4-mapped IPv6 归一化，重复、拼接或带 zone 的头不接受。

每来源 5 次失败的 15 分钟限制保留；另有短时全局登录预算、非排队的单次密码哈希和 4 KiB 登录请求限制。它们控制资源占用，不构成完整 DDoS 防护。登录失败状态当前为进程内状态，中心重启会清空。

升级启动前会为旧的已加载 Caddy 配置补齐专用头，保留端口、安全路径和已加载的证书，不把另存但尚未加载的 HTTPS 设置提前应用。正常使用管理脚本升级会一起停止和启动同机相关服务。手工替换二进制必须配套重载 Caddy；不能只更新 Go 程序而继续使用旧代理配置。

当前支持直接访问 Caddy 的部署。额外 CDN、第三方反向代理和多层可信代理策略尚未提供配置，不能宣称支持这些拓扑下的原始客户端 IP 隔离。
