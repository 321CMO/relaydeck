# RelayDeck 功能规格 v9：面向 3x-ui 老用户

更新：2026-10-15。本文是新的设计与实现要求，覆盖旧规划中以简化表单、隐藏核心术语为主的取向。当前上线版本仍为 alpha.4；本文列出的新增能力需要逐项实现和验收，不代表已经上线。

## 1. 产品与操作模型

以熟悉 3x-ui 的管理员为主要用户。完整参数、直接编辑、导入导出、批量操作和诊断效率是首要目标。按协议组织字段，不把配置缩减为仅名称、地址和端口。保持多 VPS 管理、一个订阅聚合多个授权节点、HY2 跳跃、云原生内网 A→B 和独立管理端口/安全路径。

“节点”页面明确标注为“节点 / 入站”，列表支持展开该入站的客户端。沿用“入站、出站、Tag、Flow、传输、安全、嗅探、路由规则、客户端”等术语。“订阅”保持现名，用来管理订阅身份、聚合授权和交付；入站客户端凭据与订阅身份关联，不维护两套互不相干的用户。

不把向导作为必经流程。配置采用宽弹窗或工作区，表单分为“基本 / 客户端 / 传输 / 安全 / 嗅探与连接 / JSON / 变更记录”。支持快捷复制、批量编辑、配置片段导入和完整导出；不适用的页签按协议隐藏并解释。

## 2. 对照 alpha.4 的实际缺口

| 能力 | alpha.4 实际状态 | v9 要求 |
| --- | --- | --- |
| Reality | SNI、目标、固定 Vision；自动密钥与单个 Short ID；客户端指纹固定 chrome | 完整参数与密钥管理、客户端参数可编辑、协议组合校验 |
| HY2 | 证书、连续跳跃；无可视化混淆、带宽或伪装配置 | 配置混淆、带宽、伪装、QUIC 相关选项及证书资源引用 |
| SS2022 | AES-128 固定，服务端/用户密钥自动生成 | 加密方式选择、密钥管理、网络选择与单/多用户模式校验 |
| 出站 | 五种手填表单，只有基础连接字段 | 分享链接、批量文本、订阅源、配置文件导入，完整协议参数及来源更新 |
| 入站客户端 | 从订阅编辑节点授权，凭据没有管理界面 | 入站展开客户端，可编辑/生成/轮换认证，关联订阅、显示该授权的状态与流量 |
| 路由 | 顺序/开关/条件/出站；脱敏预览 | 拖拽、导入导出、规则集管理、命中分析、DNS/出口策略与引用跳转 |
| 出口选择 | 节点只能指定受管内网落地；自定义出站经规则或全局默认选择 | 每个入站可直接选任意兼容出站，并区分默认出口和规则覆盖 |
| JSON | 路由及出站只读预览 | 可编辑的原生配置片段、表单往返与变更对比；校验后发布 |
| 操作效率 | 简单列表，无搜索和批量工具 | 筛选、列设置、多选、批量启停/复制/导出/授权、保存草稿与批量发布 |

以上是代码核对结果，不把固定值当作可配置功能，不把配置预览当作 JSON 编辑器，不把“已启用”当作出口可达。

## 3. 入站配置

### 3.1 通用字段与操作

- 名称、Tag、服务器、监听地址、监听端口、对外连接地址/端口、启用状态、标签与备注。监听地址和订阅地址分别存储，支持 IPv4/IPv6；端口映射不要求外部端口等于本机监听端口。
- 根据协议选择 TCP、UDP 或两者，界面区分监听传输与代理承载能力。例如 Reality 的 TCP 监听不能标为需要开放同端口 UDP。
- 列表支持搜索、按服务器/协议/标签/状态筛选、展开客户端、复制入站、启停、导出、批量更改。复制时明确端口、Tag、认证和授权的处理，不能复用冲突的监听端口。
- 从入站展开客户端：备注、所属订阅、UUID/密码、Flow、启用、到期、授权流量、最后上报、链接/二维码、复制与轮换认证。独立的入站客户端到期和额度需要与订阅总额度分别定义，未实现的限制不显示为可执行。
- 原配置、草稿和当前生效版本可以对比；保存草稿与发布分开。多个相关变更可一起发布，避免每改一个选项就重启核心。

### 3.2 VLESS Reality

| 分区 | 配置要求 |
| --- | --- |
| 协议 / 客户端 | UUID 手填/生成/复制/轮换，按客户端设置 Flow；默认 Vision 可修改，组合不受支持时在保存前指出 |
| Reality | 握手目标及端口、SNI、私钥/公钥、Short ID 列表及生成、最大时间差（核心支持时） |
| 订阅参数 | 默认客户端指纹、对外地址、SNI、Short ID 选择；与服务端监听配置分别展示 |
| 检查 | 握手目标 TLS 检测、密钥公私匹配、Short ID 格式与引用、传输/Flow 组合、客户端格式适配 |
| 可移植性 | 导入服务端原生配置时保留提供的密钥；仅有客户端分享链接不能据此恢复服务端私钥 |

多 SNI、客户端版本范围、SpiderX、ML-DSA、XHTTP、Sockopt 等按目标核心逐项适配。不能把 Xray 参数名称原样保存后假装 sing-box 已执行，也不能把 SNI 列表截取第一项却不说明。传输支持范围与 Reality/Flow 的合法组合由能力表决定，不把协议选择和传输选择做成任意可组合的菜单。

### 3.3 Hysteria 2

- TLS：引用证书资源、证书域名、ALPN 与可适配的 TLS 参数。面板证书和节点证书可以显式共享符合域名的资源，必须跟踪续期和实际加载版本。
- 认证：每客户端密码手填/生成/轮换；导入带 `用户名:密码` 的认证时完整保留其实际密码语义。
- 混淆：优先完成 Salamander 类型与密码，其他类型按核心和两个目标客户端的支持范围开放。
- 带宽：上/下行 Mbps、客户端带宽处理和拥塞相关可用选项；不要把这些参数称作已经实现的精确用户限速或流量额度。
- 伪装：URL / 固定响应 / 文件目录等目标核心支持形式，输入校验并展示最终配置。
- QUIC / UDP：可用的窗口、超时、UDP 相关参数；版本不支持的选项标明原因。
- 端口跳跃：监听端口、跳跃集合、间隔、nftables 规则预览和实际应用；范围或多段集合需同时验证客户端导出、服务端转发及云侧端口要求。保留 alpha.4 的连续范围兼容。

### 3.4 SS2022

- 展示并选择加密方式，先完成 AES-128 / AES-256，再按实际核心与客户端结果开放其他 SS2022 方法。
- 服务端主密钥与客户端密钥分开管理，明确 Base64 编码后解码字节数；算法变化时必须验证现有用户密钥，不能只换 method 字符串。
- 单用户 / 多用户配置需要分别校验目标核心的合法组合；算法是否支持多用户不能由 UI 推测。
- TCP/UDP 网络选择、UDP 超时等可用选项进入表单和导出；二维码与链接保留完整服务器密钥和客户端密钥语义。
- 密钥轮换展示受影响的授权和订阅，按版本确认生效。

## 4. 出站一键导入：首批实施项

出站工具栏固定提供“添加 / 导入 / 导出 / 批量操作”。导入弹窗有“分享链接 / 订阅地址 / 配置文件”入口，可直接粘贴，支持上传文本文件。已支持的完整参数必须在表单中可见、可编辑，并参与编译与导出。

### 4.1 输入格式

| 输入 | 处理要求 |
| --- | --- |
| 单条分享链接 | VLESS Reality、`hy2://` / `hysteria2://`、SS2022、SOCKS5、HTTP/HTTPS 代理；按协议明示支持范围 |
| 多行文本 / Base64 URI 集合 | 逐项解析，保留行号、名称和参数；混合有效与无效项分别报告 |
| 订阅 URL | 抓取并识别普通 URI 集合、Base64、Mihomo YAML、sing-box/Xray JSON；保存来源可手动/定时刷新 |
| Mihomo YAML | 解析代理对象；代理组作为独立对象处理，不能随意取第一项变成出站 |
| sing-box JSON | 单个 outbound、数组、完整配置中的 outbounds；解析依赖和引用 |
| Xray JSON | 单个 outbound、数组、完整配置中的 outbounds；做有明确能力边界的映射，不能原样塞进 sing-box |

VLESS 普通 TLS、Trojan、传统 SS、VMess、WireGuard 等常见外部出口纳入后续适配清单；对尚未支持的项必须报告具体协议/参数。此清单不自动扩大当前三个服务端入站协议的范围。

### 4.2 导入过程与参数保真

1. 粘贴内容或 URL，自动识别格式；选择目标 VPS 和名称/Tag 生成策略。
2. 展示逐项结果：可完整导入、待补字段、目标核心不支持、语法错误、已有重复项。显示名称、协议、地址、传输、安全、来源和问题字段。
3. 支持勾选、批量重命名、保留/覆盖/新建重复项；默认选择可完整导入的记录。零错误时可一次确认导入，不强制逐字段手填。
4. 在落库前处理 Tag 冲突与链式引用；批量提交使用事务。导入出站不会隐式改变现有默认出口或路由。
5. 导入后允许直接“用于指定入站 / 用于路由规则 / 设为默认出站”，显示生效版本；TCP 探测、协议握手与 UDP 测试分别报告。

必须覆盖：URL 转义、中文名称、IPv6、非 443 端口、密码含冒号/`@`/`#`、标准/URL-safe Base64、空行、重复名称、HY2 混淆和跳跃、SS2022 单密钥/多级身份密钥、VLESS Flow/公钥/Short ID/指纹/传输参数。原始查询参数保留到解析记录，不能丢字段后给“成功”。

导入内容携带未支持、影响协议语义的字段时阻止该项发布，并解释字段路径。原始资料可以保留为待适配记录，不让未支持的 JSON 绕过编译器进入运行配置。原始输入和凭据加密保存、日志和预览脱敏。

### 4.3 订阅来源刷新

来源与实际出站分开记录，稳定 ID 关联路由。刷新预览新增/变更/消失项，支持来源筛选、定时周期、手动刷新、失败原因和上次成功时间。上游换端口、密码或备注不能打断稳定引用。源内容无法可靠识别同一记录时显示待确认匹配，不按数组位置盲目覆盖。

网络错误或空响应保留上次有效配置。源删除了仍被引用的出站时标为“来源已移除，仍有引用”，保留末次配置并告警，不能删完后自动变成直连。导入的外部出口凭据留在服务端；向朋友发布的是受管入站凭据。

## 5. 出站完整编辑与出口指定

| 分区 | 要求 |
| --- | --- |
| 基本与认证 | 名称、Tag、地址、端口、协议、认证、备注、来源、启用 |
| 传输与安全 | 按协议支持的传输、SNI、ALPN、指纹、Reality 公钥/Short ID、HY2 混淆/带宽/跳跃、SS 加密方式 |
| 拨号与 DNS | 超时、DNS 策略/解析器、绑定源地址/网卡、IP 版本偏好等目标核心可执行字段 |
| 代理链 | 可视化前置出站与依赖，循环检查、TCP/UDP 兼容检查；HY2 不能经过仅 TCP 的 HTTP 前置出口 |
| 工具 | 测试连接、协议握手、UDP 检查、出口 IP 查询、复制分享链接、导出配置、引用查询 |

每个入站可以选择“继承服务器默认 / 明确直连 / 指定出站 / 受管内网落地”。明确直连和继承默认要使用不同存储值。节点列表展示实际默认出口；路由仍可覆盖该兜底，命中分析展示覆盖关系。

A→B 原生内网转发作为系统管理的出站和内部入站保留。提供详情、两端版本、日志和引用查询；不允许普通规则覆盖内部入站直出而形成回环。不能把外部导入的节点误当成已由 Agent 管理的落地机。

## 6. 路由、DNS 与 JSON 编辑

- 路由表保留现有条件，补齐拖拽排序、批量操作、导入/导出、规则集来源和更新时间、失效引用定位。
- 路由测试输入入站、订阅/客户端、域名或 IP、端口、网络和协议，显示命中顺序及最终出口。静态推演和运行核心观察分别标注；域名解析、嗅探改变匹配信息时需要解释。
- 默认出口、入站出口、规则优先级可直接查看。出口类型、标签或来源更新后稳定引用保持；删除前能打开引用对象。
- DNS 具备独立配置和可复用解析器，避免只能修改硬编码订阅模板；服务端 DNS 与客户端 DNS 分区。
- 服务端出口组、健康检查、故障转移和负载均衡按核心实际策略实现；显式配置所有候选不可用时的行为。保留选择代理后失败阻断的默认语义。
- 原生 JSON 编辑采用协议片段/路由片段和完整渲染预览。表单/JSON 切换不能丢失合法扩展字段。平台保留字段（Agent 身份、内部监听、统计接口、管理端口保护）受编译器约束；越界修改解释冲突。
- 先保存草稿、执行原生解析检查、显示差异，再一次发布。Agent 校验和回执、失败恢复、变更记录沿用已验证机制；跨 VPS 显示部分成功。

## 7. 核心差异与实施边界

当前运行 sing-box 1.14.3，3x-ui 主要配置 Xray。以下类别分别处理：

| 类别 | 处理方式 |
| --- | --- |
| 目标核心已经支持，只是面板未开放 | 优先补字段、编辑、编译与客户端导出，如 Flow、指纹、Short ID 管理、HY2 混淆、SS 算法 |
| 两边概念相近但字段语义不同 | 写显式适配器和保真测试，展示映射结果，例如传输、DNS 策略、拨号字段 |
| Xray 专有或当前固定核心不支持 | 显示具体限制，进入 Xray 适配器/双核心评估；不能用无效开关冒充支持 |

完整 Xray JSON 和 XHTTP 等不能靠扩大表单完成兼容。双核心需要独立的进程/端口分配、配置编译、用户统计、跨核心路由与故障恢复设计，不把它夹在普通字段更新里直接替换现有线上核心。

新增参数的完成条件是：数据可保存 → 核心接受并实际执行 → 客户端导出保真 → 重启/升级保留 → 编辑与导入导出不丢字段。按“已实现 / 已通过核心检查 / 已实测 / 核心不支持 / 客户端待验证”记录，不能只记一个总的完成勾选。

## 8. 实施顺序与验收

| 批次 | 内容 | 最低验收 |
| --- | --- | --- |
| P0-A | 三协议分享链接与批量出站导入；完整参数映射；导出与重复项处理 | 端口/编码/IPv6/认证不改变；不支持参数明确失败；真正出站 TCP/UDP 连接；重启后引用保留 |
| P0-B | 节点 / 入站完整编辑、Reality 密钥/Short ID/Flow/指纹、HY2 混淆与带宽、SS2022 算法与密钥 | 表单、核心配置、订阅参数三者一致；现有节点凭据默认不变；两客户端兼容结果记录 |
| P1-A | 原生 JSON/Mihomo 文件和订阅 URL 导入、来源刷新、入站客户端管理、批量授权与发布 | 刷新稳定引用、失败保留有效配置、同一订阅身份授权与凭据一致 |
| P1-B | 拨号/DNS、出口组、路由命中分析、JSON 往返、连接及出口 IP 测试 | TCP 可连与协议可用分别记录；UDP 单独验证；故障行为符合设置 |
| 能力扩展 | Xray 适配器及其专属传输/安全功能 | 架构与统计/路由/升级恢复验收通过后才标为支持 |

P0 两项是本轮方向调整后的首批开发范围，不再以菜单已存在作为“功能齐全”的依据。

实现时先扩展数据模型：入站分别存储监听配置、协议配置和客户端导出默认值；授权记录存储凭据及 Flow 等覆盖值；订阅来源、导入记录与实际出站独立。原生扩展携带核心类型和版本，经过对应 schema/核心检查后合并。需要有正式数据迁移和备份兼容测试，旧节点的 UUID、主密钥、用户密钥、订阅 token 与稳定引用在迁移中保留，不能通过删除重建来“补齐字段”。
