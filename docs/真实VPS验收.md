## 实机发现并修复

1. Caddy 默认 HTTP/3 会占用 UDP 443。中心配置与首次安装模板显式使用 HTTP/1.1、HTTP/2，保留 UDP 443 给 HY2，加入官方 Caddy 适配结果回归检查。
2. 恢复旧备份时，Agent 生效版本可能高于中心旧版本而持续被拒绝。恢复生成新代次、清零旧回执，并按代次隔离 Agent 配置目录；新代次实际应用后才发布订阅。恢复后的数据使用 schema 2，旧程序拒绝打开，避免静默忽略代次。
3. 已保留身份的 Agent 重装不应再索取过期安装码。CLI 先检查身份并验证中心及服务器归属，再决定是否读取一次性安装码。
4. 恢复的 HTTPS 加载状态失效，需重新加载验证，不能沿用另一实例的状态。

HTTP 回显目标在测试中补齐 Content-Length；不把测试目标自身关闭连接导致的问题归为协议缺陷。

## 原有三节点切换到内网落地（2026-10-17）

用户明确同意统一切换后，先重新确认两台机器、当前节点集合、Agent 与 HTTPS 状态，创建并校验新的不停机加密恢复点，再变更原有 Reality、HY2、SS2022 节点的落地引用。未替换管理端口、安全路径、节点 ID 或订阅认证。

- 两端真实 Agent 的目标和应用版本追平，原有 3 节点均引用 B；最终仍为 2 台服务器、3 个节点、2 份订阅，没有遗留隔离验收节点或测试订阅。
- 两份原聚合订阅的 URI 内容与切换前逐字一致，客户端继续使用原订阅地址。
- 两位原订阅使用者的三协议真实 TCP/UDP 均通过；域名目标可达，自管目标观测到 B 的公网出口 IP。
- 原 HY2 跳跃范围的首、中、末端口，以及定时跳跃的 TCP/UDP 通过。
- 当日未再停止承载原订阅的 B 进行故障注入；不直出回退的故障证据来自前一日同版本、相同原生内网链路的隔离验收。
- 临时回显服务测试后关闭，管理入口、原账号与密码继续保留。B 原有独立 sing-box 服务保留。

本次仅切换已验证的线路，未将项目发布为商用稳定版。自动离机备份、中心失联策略、容量与长期运行、真实 TG、证书续期和客户端完整矩阵继续按商用审查跟踪。
