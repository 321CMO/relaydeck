## 一、当前已确认的问题

### UX-001 · P2 · 成功提示不自动消失，退出后仍可残留

- 证据：**浏览器复现、用户截图**。登录成功后等待超过 7 秒，提示仍存在；退出登录后，登录页还可能显示上一轮“登录成功”。
- 原因位置：[全局 notice 与提示渲染](../web/src/main.tsx#L20)、[登录/退出流程](../web/src/main.tsx#L32)。只有手动清空，没有自动关闭计时；退出未清理旧成功消息。
- 完善要求：普通成功提示默认约 3 秒自动关闭，可手动关闭；同文案连续操作也应重新计时。切换账号/退出时清理旧提示。长任务进度、需用户处理的错误和改密后的重新登录说明，应分别管理，不能用一个定时器全部隐藏。
- 验收：登录、复制、保存等普通成功提示按时消失；退出后不出现旧登录成功提示；新提示不会被上一条计时器提前清除。

### UX-002 · P1 · 出站预览与实际导入内容可能不一致

- 证据：**浏览器复现**。解析旧链接时延迟返回，在文本框改成新链接后释放响应；界面展示旧链接的预览，却能提交并导入新链接。
- 原因位置：[异步解析与输入更新](../web/src/OutboundImport.tsx#L9)、[预览快照验证](../internal/panel/outbound_import.go#L449)。解析中仍能编辑；旧响应可覆盖新输入的预览状态。服务端快照检查已有出站状态，没有绑定本次输入内容。
- 完善要求：预览绑定目标服务器、输入内容摘要与请求序号；输入改变即作废旧响应。提交使用已确认的那份内容，服务端同时验证内容摘要。解析与提交期间的可编辑范围必须明确。
- 验收：慢请求返回、连续改输入、读取另一文件、覆盖重复项等情况，都不能提交未预览的配置。

### UX-003 · P1 · 旧设置表单会覆盖其他标签页的新设置

- 证据：**浏览器复现**。保持设置页邮箱输入未保存；模拟另一标签页将客户端预设改为“全部代理”；原设置页保存邮箱后，预设被旧值覆盖。
- 原因位置：[整份 Settings 提交](../web/src/main.tsx#L68)、[整份设置替换](../internal/panel/app.go#L637)。没有分区更新或版本冲突检查。
- 完善要求：HTTPS、TG、客户端分流等按修改字段或独立分区保存；同一分区使用版本校验，冲突时展示差异并保留当前输入。
- 验收：修改邮箱不改变另一标签页刚保存的分流预设或 TG 设置；同一字段冲突不能静默覆盖。

### UX-004 · P1 · 写入成功但刷新失败，重试会重复创建服务器

- 证据：**浏览器复现**。服务器创建接口返回 200，紧随其后的列表刷新返回 503；创建侧栏显示错误并重新允许保存，再点一次后产生两台同名服务器记录。
- 原因位置：[保存与刷新放在同一失败处理内](../web/src/main.tsx#L33)。新服务器 ID/注册码在刷新完成前没有进入可恢复的交互状态。
- 完善要求：区分“写入未完成”“写入已成功、列表刷新失败”“结果待核对”。写入成功后保存返回对象，只重试读取；创建请求增加幂等标识，响应丢失时先核对结果。
- 验收：创建后刷新失败、网络中断和重试均不产生重复对象；能找回已创建服务器并继续登记。节点、订阅、出站与规则创建一并检查。

### UX-005 · P1 · 未保存的编辑内容可直接丢失

- 证据：**浏览器复现**。修改节点名称后按 Esc 关闭，重新打开内容丢失且没有提示；修改设置后切到其他页再返回，输入同样丢失。
- 原因位置：[侧栏关闭与 Esc](../web/src/main.tsx#L29)、[遮罩关闭](../web/src/main.tsx#L53)、[设置页局部状态](../web/src/main.tsx#L66)。路由/出站侧栏也缺少统一的脏状态保护。
- 完善要求：仅在实际存在未保存改动时，关闭、切页、刷新或改密跳转前提示“继续编辑 / 放弃更改”；长期编辑可增加草稿恢复。没有改动时直接关闭，不增加无意义确认。
- 验收：节点、订阅、出站、规则、HTTPS/TG 均覆盖；点击遮罩、Esc、关闭、取消及离页行为一致。

### UX-006 · P1 · 入口端口校验连带阻止 HTTPS/TG 设置保存

- 证据：**浏览器复现**。将管理端口输入设为 1000，即使不点击应用入口，外层“保存设置”所在表单也变为无效。开发模式无管理端口时的初始值 0 也会触发。
- 原因位置：[入口端口输入校验](../web/src/AccountSecurity.tsx#L22)、[嵌入 HTTPS/TG 共用表单](../web/src/main.tsx#L70)。独立操作共享了原生表单校验范围。
- 完善要求：账号、入口、HTTPS、TG 各自提交和校验；无效入口草稿只阻止入口应用。开发模式无已配置管理入口时，应显示明确状态。
- 验收：入口草稿无效不阻止保存 TG 或证书；关闭入口折叠区后，也不会出现隐藏字段导致无法保存的情况。

### UX-007 · P1 · 后台刷新失败时，界面继续展示旧状态且无提示

- 证据：**浏览器复现**。对状态轮询返回 503，等待超过一个轮询周期，页面仍显示旧列表，没有错误、数据过期或重连提示。
- 原因位置：[15 秒轮询吞掉错误](../web/src/main.tsx#L26)、[首次加载失败页面](../web/src/main.tsx#L40)。首次会话加载失败也没有直接重试入口。
- 完善要求：显示最近一次成功更新时间、刷新失败/重连状态及手动重试；旧数据保留但明确标注。浏览器连接失败不能直接推断所有 Agent 或代理节点离线。
- 验收：网络中断、502/503、恢复和会话过期分别反馈；恢复后清除过期标记，失败时不继续暗示实时正常。

### UX-008 · P2 · 未保存配置与“测试/加载”的对象不够明确

- 证据：**浏览器复现**。表单改成新域名后点击加载，接口仍读取旧域名；输入新 Bot Token 后验证，服务端仍验证已保存 Token。本机原 Token 为空时，返回“请填写有效的 Bot Token”。
- 原因位置：[HTTPS/TG 操作按钮](../web/src/main.tsx#L70)、[HTTPS 读取已保存设置](../internal/panel/https.go#L84)。TG 按钮确实标注“已保存”，服务端按现有语义工作，问题在于整体编辑与验证流程不直观。
- 完善要求：清楚显示“未保存修改”；提供“保存并验证”或在脏状态下说明当前将验证哪个版本。HTTPS 展示已保存/已加载版本，TG 展示本次测试接收目标。
- 验收：用户能判断测试的是表单新值还是已保存值；不能在旧配置测试成功后让人误以为新配置已生效。

### UX-009 · P1 · 面板证书只更换私钥时，新输入会被忽略

- 证据：**源码确认**。[设置保存逻辑](../internal/panel/app.go#L660) 在证书链留空时同时恢复旧证书和旧私钥，即使请求提供了新私钥。
- 完善要求：证书和私钥各自按“留空沿用”处理，再校验最终配对；不匹配时明确报错。可要求成对替换，但必须明确拒绝不完整变更，不能静默丢弃输入。
- 验收：只传证书、只传私钥、成对替换和全部留空分别有确定结果；错误配对不能显示保存成功。

### UX-010 · P1 · 配置失败有状态，缺少可直接使用的原因与定位入口

- 证据：**源码确认**。服务器和任务模型含 `error`，列表主要展示“应用失败”徽标；总览只显示最近 5 条任务的摘要/状态，没有错误详情或完整任务入口。
- 位置：[服务器与最近任务](../web/src/main.tsx#L46)、[任务错误字段](../internal/panel/model.go#L114)。
- 完善要求：从失败对象进入任务详情，显示失败阶段、服务器、版本、脱敏原因、时间、受影响对象和重试结果；明确上一份配置是否仍运行。
- 验收：端口占用、核心检查失败、证书失败、Agent 失联与落地不可达能分别定位；不需要翻终端猜测失败原因。

### UX-011 · P1 · 订阅交付缺少“当前实际可用节点”预检查

- 证据：**源码确认**。后台可为未应用或无授权节点的订阅打开交付侧栏并复制地址；订阅服务会拒绝无已应用节点的导出，后台没有对应的就绪数量和原因摘要。
- 位置：[订阅列表及交付侧栏](../web/src/main.tsx#L49)、[实际订阅节点筛选](../internal/panel/subscription.go#L18)、[未就绪时返回 503](../internal/panel/subscription.go#L177)。现有服务端发布门槛应保留。
- 完善要求：分别显示授权总数、已应用可交付数、待应用/停用/到期数；0 个就绪节点时明确“暂不可导入”，仍允许管理员预先获取地址，但不能暗示已经可用。
- 验收：空授权、全部待应用、部分 VPS 离线、部分节点就绪、订阅停用和到期都有明确结果。

### UX-012 · P1 · 删除与共享密钥轮换缺少具体影响预览

- 证据：**源码确认**。删除确认主要为通用说明；删除节点会移除所有相关订阅授权。SS 算法/主密钥轮换虽已有确认框，但没有列出受影响订阅与刷新要求。
- 位置：[删除确认](../web/src/main.tsx#L59)、[节点删除对授权的影响](../internal/panel/app.go#L478)、[SS 轮换确认](../web/src/NodeFields.tsx#L14)。已有引用阻止机制应保留。
- 完善要求：执行前展示关联服务器、节点、订阅、规则/代理链及影响数量，提供依赖跳转；区分停用、撤销授权、移除记录和卸载机器。
- 验收：能在确认前判断哪些朋友会断开、哪些客户端要刷新；改备注等普通操作不额外弹确认。

### UX-013 · P2 · 多 VPS 的路由操作上下文丢失

- 证据：**浏览器复现**。选择第二台 VPS 后切到节点页，再回分流页，服务器选择恢复到第一台，页签也恢复默认。
- 原因位置：[路由页局部初始化](../web/src/RoutingPage.tsx#L22)。
- 完善要求：保留最近选定的服务器、页签和筛选，必要时放入 URL；目标被移除时明确提示。新建规则、导入与发布始终醒目标注目标 VPS。
- 验收：跨页返回、刷新和浏览器返回后的上下文符合预期，不会因为组件重建把操作带回另一台机器。

### UX-014 · P2 · 传输能力展示和导出没有完全跟随配置

- 证据：**源码确认**。出站列表除 HTTP 外统一显示 TCP/UDP，没有反映 SS2022 的 `network`；Clash 代理基础对象统一设置 `udp: true`，需针对 SS“仅 TCP”等配置检查最终导出语义。
- 位置：[出站列表能力说明](../web/src/RoutingPage.tsx#L52)、[订阅代理基础字段](../internal/panel/subscription.go#L76)。
- 完善要求：建立入站监听、出站承载、协议链能力和客户端导出的对应关系；展示能力来源。客户端表达不了的限制要明确说明，不能显示为完整支持。
- 验收：SS 仅 TCP、仅 UDP、TCP+UDP，HTTP 仅 TCP，HY2 经不同代理链等组合分别检查 UI、核心配置与两个目标客户端输出。此条尚未完成对应客户端实测。
